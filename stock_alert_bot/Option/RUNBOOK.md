# Stock Alert Bot Runbook

This project fetches live NSE option-chain data, optionally tries Dhan first, analyzes option positioning and price action, and stores snapshots for future research.

## 1. Open the project

In PowerShell:

```powershell
cd C:\Users\Kunal\Desktop\Stock\stock_alert_bot
```

## 2. Install dependencies

Create and activate a virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, run the project with the virtual-environment executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 3. Configure the data source

Edit `config/settings.json`:

```json
{
  "symbol": "NIFTY",
  "data_source": "dhan",
  "refresh_minutes": 5,
  "trend_analysis_interval_minutes": 5,
  "enable_order_execution": false
}
```

Supported symbols include `NIFTY`, `BANKNIFTY`, and symbols supported by the selected provider.

`data_source: "dhan"` means Dhan is tried first and NSE is used automatically if Dhan fails. Use `data_source: "nse"` to use NSE directly. Use `data_source: "mock"` only for offline testing.

The browser refreshes the displayed values every 2 seconds. The confirmed trend is evaluated only after `trend_analysis_interval_minutes`. Use `1`, `2`, `5`, `10`, or `15` according to your research needs.

## 4. Dhan credentials

Never commit access tokens or secrets.

Set the client ID for the current PowerShell session:

```powershell
$env:DHAN_CLIENT_ID = "your_client_id"
```

Put the current access token in:

```text
data/dhan_access_token.txt
```

The file is ignored by Git. A Dhan token can expire, so refresh it when Dhan reports authentication failure. The application will then try NSE automatically.

## 5. Run the web dashboard

From the project root:

```powershell
python scripts/web_dashboard.py
```

Open this address in a browser:

```text
http://127.0.0.1:5000
```

The dashboard displays:

- Live spot price and data source.
- PCR based on OI and volume.
- Max pain.
- Support and resistance zones.
- Call and put OI buildup.
- Call and put volume flow.
- Price-action direction and 20-session SMA.
- ATM Greeks: delta, gamma, vega, and theta.
- Top strikes by total OI.
- Trend-change alerts after the configured comparison window.

Stop the server with `Ctrl+C`.

## 6. Capture a manual snapshot

Capture live NSE data:

```powershell
python scripts/capture_snapshot.py --symbol NIFTY --source nse
```

Capture through Dhan:

```powershell
python scripts/capture_snapshot.py --symbol NIFTY --source dhan
```

The command writes both the raw snapshot and flattened CSV data.

## 7. Data folders

```text
data/live/
```

Contains the newest live response for each symbol, for example `NIFTY_latest.json`.

```text
data/history/YYYY-MM-DD/
```

Contains timestamped raw JSON and a flattened option-chain CSV. The web dashboard saves historical data approximately every five minutes per symbol.

```text
data/analysis/
```

Contains historical summaries generated by the analysis command.

These folders are ignored by Git so local market data and generated files do not enter the source repository.

## 8. Analyze historical data

After collecting snapshots, run:

```powershell
python scripts/analyze_history.py --symbol NIFTY
```

The output includes one row per saved snapshot with:

- Call OI and put OI.
- Call volume and put volume.
- OI PCR.
- Volume PCR.
- Put-minus-call OI imbalance.
- Put-minus-call volume imbalance.

The summary is also saved to:

```text
data/analysis/NIFTY_history_summary.csv
```

You need multiple snapshots across time before meaningful buildup or strategy research is possible.

## 9. Backtest the strategy

Run the walk-forward backtest after collecting dated option snapshots:

```powershell
python scripts/backtest_strategy.py --symbol NIFTY --period 5y
```

The strategy combines price action, candlestick shape, OI PCR, put-minus-call
OI imbalance, and put-minus-call volume imbalance. It produces `LONG`, `SHORT`,
or `FLAT` only when at least three confirmations agree. The signal is applied
to the next available daily close to avoid look-ahead bias.

The report includes observations, trades, win rate, total return, and average
trade return. A one-day or one-snapshot archive is intentionally reported as
`insufficient_history` and must not be used to judge a strategy. Collect at
least 3 months of snapshots; 1 year or more is better for regime comparison.

The backtest is a research baseline. It does not yet include brokerage costs,
slippage, position sizing, option contract selection, or execution latency.

## 11. Understand the trend output

The system should be read as a confirmation tool, not a prediction engine.

### Price action

- `Bullish price action`: latest close is above the 20-session SMA and increased from the previous close.
- `Bearish price action`: latest close is below the 20-session SMA and decreased from the previous close.
- `Mixed / range-bound price action`: price and moving-average evidence disagree.

### OI side

- Put OI building more can indicate put-side support and an upward bias.
- Call OI building more can indicate call-side resistance and a downward bias.
- Both sides building similarly can indicate a sideways or range-bound market.

OI alone is not enough. Call and put buildup can represent buying or writing, so the per-strike buildup label and option price movement must be considered.

### Buildup labels

- `Long Buildup`: option price and OI both increased.
- `Short Buildup`: option price decreased while OI increased.
- `Short Covering`: option price increased while OI decreased.
- `Long Unwinding`: option price and OI both decreased.
- `Flat / Unclear`: no meaningful change.

### Confirmed trend

The confirmed trend is only updated after the selected comparison interval and requires agreement between option-chain analysis and price action:

- Bullish option read plus bullish price action: `Bullish trend`.
- Bearish option read plus bearish price action: `Bearish trend`.
- Conflicting evidence: `Mixed / neutral trend`.

## 12. Troubleshooting

### Dhan authentication failed

Refresh the access token and set the matching `DHAN_CLIENT_ID`. NSE fallback should still be attempted automatically.

### NSE data failed

Check internet access, verify that NSE is reachable in a browser, and retry outside unusual traffic bursts. The program will not substitute mock prices for failed live data.

### Browser appears blank or stale

Confirm the server is running, then open:

```text
http://127.0.0.1:5000/
```

Use `Ctrl+F5` to force a browser refresh. The API health check is:

```text
http://127.0.0.1:5000/api/trend
```

A successful response returns HTTP 200 and JSON containing `dashboard`, `flow`, `greeks`, `price_action`, and `source`.

### No historical files found

Run `capture_snapshot.py` or keep the web dashboard running during market hours. NSE does not guarantee a complete historical option-chain archive, so the bot must collect snapshots over time.

## 12. Safety

`enable_order_execution` is disabled by default. Do not enable live order execution until broker credentials, symbol mapping, quantity, product, and order safeguards have been independently verified. This project provides market analysis and alerts; it does not guarantee profitable trades.
